# MAA 更新中断与境外大文件链路检查（2026-10-21）

## 证据与结论

- 桌面快捷方式指向源码入口 `scripts/run-local.ps1`。最近失败发生于 `update_maa`，退出码为 1，标记为 `core_install_failed`。
- 隔离安装复现 `Failed to install MaaCore`，底层原因为 `I/O error / Peer disconnected`。另一次出现 TLS 未发送 `close_notify` 就关闭连接。
- 系统代理和代理环境变量未启用，但 sing-box 的 TUN 已启用，默认流量经本机 Xray。显式指定本机 HTTP 代理不能绕开同一远端出口，所以这两种测试不能视为独立的公网直连和代理线路对照。
- 隔离 Xray 测试中，当前节点、关闭 ECH、改用 443 端口以及另一 Worker 节点均曾提前断流。没有更改正在使用的 v2rayN 配置；这些结果不能进一步确定是远端服务实现、出口还是中间网络造成中断。

## 源码修复

新增 `maa_update.runtime.MAAUpdateAdapter`，仅用于默认生产绑定的 MAA 更新阶段。普通任务仍使用原有 `MAAAdapter`。

- 只对包含 MaaCore 安装失败及已知网络中断提示的非零退出进行重试；必须确认子进程已清理。
- 让 maa-cli 使用原有 `.partial` 文件断点续传，不自行修改部分包，也不跳过 CLI 校验。
- 连续五次无下载进度即停止；有进度可继续，最多调用 512 次。使用下载缓存大小的历史最大值判断进度，避免缓存被清空重写造成虚假进度。
- 全部尝试共享配置和父级的总截止时间。重试等待支持取消；解压、权限、资源仓库及游戏任务错误不会因此自动重试。
- 报告增加安全计数 `update_attempts` 和固定标记 `download_interrupted`，继续过滤原始输出和路径。
